Why I Write This Blog

Every article on this blog started as a problem I actually hit in production or while learning something new. The debugging session that took three hours. The configuration change that fixed a cryptic SSL error. The command that finally made a Docker networking issue make sense.

I write them up for two reasons. First, writing forces me to understand the problem completely — I can't hand-wave a vague fix in prose the way I can quietly move on from one in a terminal window. Second, these exact problems are the ones other developers search for at 11 PM when a deployment is broken and Stack Overflow doesn't have a clean answer. If one of these articles saves someone an hour, that's enough.

I make a deliberate choice to include real terminal output, real error messages, and real code from actual projects — not sanitised pseudo-examples. That's what makes a technical article genuinely useful versus one that looks complete but doesn't actually help.
